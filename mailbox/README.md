# ファイル郵便ポスト（Mailbox パターン）

直接接続できないAI同士が、両者の到達できる共有フォルダ（Google Drive、Syncthing、NAS等）を使って指示と成果物を受け渡すための規約。

## フォルダ構成（例）

```
mailbox/
  inbox/     … 指示タスクファイル置き場（依頼者 → 実行者）
  outbox/    … 成果物＋REPORT置き場（実行者 → 依頼者）
  archive/   … 完了済み（依頼者が確認後に移動）
```

## 指示タスクファイルの規約

- ファイル名：`YYYYMMDD-HHMM-<slug>.md`
- 中身は「前提の全文」を書く。要約や口頭の補足に依存しない（要約は前提を書き換える事故のもと）。
  必須項目：依頼文そのまま / 書き込み可能なフォルダ（1つだけ明示）/ 成果物の正確なパス / 期限 / 完了条件。
- 実行者はタスクファイルを唯一の前提源とし、途中経過は別ファイル（STATE）に分けて書く。

## 返信の規約

- 成果物と一緒に `REPORT.md` を置く：成果物パス・サイズ・閉じ確認（ファイルとして完結しているか）・検証結果・未完了事項。
- **最終行マーカー**：全ツールの出力と同様、最後の行を `*_OK` / `*_DONE` / `*_FAILED <reason> next: <what to try>` の形にし、受け手が機械判定できるようにする。
- 成果物も報告も無い終了は「失敗」として扱い、理由を残す。無言で終わらない。

## 運用のコツ

- 受け手は定期確認（ポーリング）で inbox を見る。間隔が遅延を決める。即時性が要る連携には使わない。
- 大きな成果物は分割して書き、組立ツールで末尾マーカーを検証してから結合する（途中切断で壊れたファイルを成果物にしない）。
- 同じフォルダを複数AIが触る場合は、対象フォルダ単位でロック（所有者・期限付きのロックファイル）を置く。
- 秘密情報は置かない（`../SECURITY.md` 参照）。
