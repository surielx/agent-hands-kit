Setup Guide

What you need

Only a Windows PC and an internet connection are required. The apps are "install only what you want to use".

Way A — Let an AI agent do it (easiest)

If you have an AI that can run commands on your PC — Claude Code, the Claude desktop app's coding features, OpenAI Codex, or a local LLM with shell access — this is the shortest path. Prepare the PC, paste the link, and say one sentence.

What happens next? The AI fetches the repository, builds the Desktop Agent, registers its startup task, places the tools, and verifies each part. Your job is only to watch and answer if it asks something. Expect a few minutes, most of it the first build.

Way C — Manual setup (all steps)

Install only the parts you will use. The Desktop Agent is the core; everything else is optional and independent. Commands can be pasted into PowerShell as-is.

Step 0 — Get the files

  1. Download the kit

    On the GitHub repository page, click Code → Download ZIP and unzip it anywhere (for example C:\agent-hands-kit). If you have git: git clone https://github.com/thanatos333/agent-hands-kit.git works too.

Step 1 — Desktop Agent (the hands and eyes)

  1. Install the .NET 10 SDK

    Free from Microsoft's site. Afterwards, reopen PowerShell and run dotnet --version — if a version prints, you are good.

  2. Build and place the agent

    Run this inside the unzipped folder. The location is fixed: %USERPROFILE%\tools\desktop-agent\.

    dotnet publish components\desktop-agent -c Release -o $env:USERPROFILE\tools\desktop-agent
  3. Register the logon task

    The task name must be exactly AronaDesktopAgent — the client looks for that name.

    $exe = "$env:USERPROFILE\tools\desktop-agent\desktop-agent.exe"
$action    = New-ScheduledTaskAction -Execute $exe -Argument "serve"
$trigger   = New-ScheduledTaskTrigger -AtLogOn
$principal = New-ScheduledTaskPrincipal -UserId $env:USERNAME -LogonType Interactive -RunLevel Highest
Register-ScheduledTask -TaskName "AronaDesktopAgent" -Action $action -Trigger $trigger -Principal $principal
Start-ScheduledTask -TaskName "AronaDesktopAgent"

    On first start, the agent creates its own access token automatically — you never need to touch it. A tray icon means it is resident.

  4. Verify (do not skip this one)

    Show the status, then take a test screenshot.

    & $env:USERPROFILE\tools\desktop-agent\desktop-agent.exe status
& $env:USERPROFILE\tools\desktop-agent\desktop-agent.exe screenshot --scale 0.5

    The screenshot lands in %USERPROFILE%\tools\desktop-agent\shots\. Open it: if it shows your desktop, the agent sees. From here, an AI can drive the desktop through desktop.ps1. Full command list: components/desktop-agent/README.md in the repository.

Step 2 — PowerShell tools

  1. Pick a home folder and copy

    For example, create C:\agent-home and copy the contents of components\powershell-tools\ and components\app-wrappers\ into C:\agent-home\tools\.

  2. Set the AGENT_HOME variable

    The tools use this as their home. Set it once:

    [Environment]::SetEnvironmentVariable('AGENT_HOME', 'C:\agent-home', 'User')
  3. Try one in a new PowerShell window

    Reopen the window (so it reads the variable), then:

    powershell -ExecutionPolicy Bypass -File C:\agent-home\tools\tool-help.ps1

    If Windows says script execution is disabled, the -ExecutionPolicy Bypass flag in the examples handles it per run. The full list is in components/powershell-tools/INDEX.md. A few tools (like delegate.ps1) are working examples from the author's own setup — adapt them before use.

Step 3 — App wrappers

  1. No configuration — test with the image preview

    Wrappers locate installed apps automatically. Start with img-peek, which needs no creative app:

    powershell -ExecutionPolicy Bypass -File C:\agent-home\tools\img-peek.ps1 -Image C:\path\to\any.png
# success = the last line starts with IMGPEEK_OK
  2. Run an app you installed

    Example: have Blender execute your script.

    powershell -ExecutionPolicy Bypass -File C:\agent-home\tools\blender-run.ps1 -Script C:\path\to\your_script.py

    Success is judged by the declared output files, not just the exit code. Details: components/app-wrappers/INDEX.md.

Step 4 — VOICEVOX harness (optional, Japanese speech)

  1. Prepare VOICEVOX and Python

    Install VOICEVOX from its official site (default location is fine), and have Python 3 ready.

  2. Place the harness and create a virtual environment 
    copy components\voicevox-harness\vv_harness.py C:\agent-home\tools\
copy components\voicevox-harness\vv-say.ps1   C:\agent-home\tools\
cd C:\agent-home\tools
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install numpy soundfile
  3. Make it speak

    Speaker 10 is Amahare Hau (normal style). The engine starts automatically if VOICEVOX is not running.

    powershell -ExecutionPolicy Bypass -File C:\agent-home\tools\vv-say.ps1 -Text "はじめまして。私の声、聞こえてますか？" -Speaker 10
# success = the last line starts with VV_OK — play the WAV and listen

    Before synthesising, the harness prints the accent/pitch plan; afterwards it verifies the output by measuring its pitch (F0) contour. Details: components/voicevox-harness/README.md.

Notification watcher (optional) — a helper that turns Windows notifications into events for agents. Source: components/notification-watcher/. Safe to skip on day one.

Connecting your AI

AI on the same PC

Works as-is

Claude Code, a local LLM, or any agent running on this PC can run the commands above directly. The component READMEs and INDEX files are written to be read by AIs — just point yours at them.

AI in the cloud

It needs one path to the PC

Combine SSH over a private network (e.g. Tailscale) for commands with a shared folder as a "file mailbox" for instructions and results. The Desktop Agent itself is never exposed — it only ever listens inside the PC. The design lives in the repository's mailbox/ and patterns/.

Final check — the two-minute drill

Whichever way you installed, finish with this.

  • Take a screenshot with the Desktop Agent and have your AI describe what is on screen
  • Pass that screenshot to img-peek.ps1 and confirm the last line is IMGPEEK_OK ...
  • (If you installed the VOICEVOX harness) synthesize one line and confirm VV_OK

If all three pass, your AI has eyes and hands. With the kit installed, an AI can even model in a CAD app by itself — see the worked example.

Troubleshooting

SymptomWhat it means / what to do
dotnet not recognizedThe .NET SDK is not installed, or the window predates the install. Install the SDK and open a new PowerShell window.
"Running scripts is disabled"Use -ExecutionPolicy Bypass per run (as in the examples), or run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once.
"Token file not found" / cannot reach the serverThe Desktop Agent is not running. Start it with Start-ScheduledTask -TaskName "AronaDesktopAgent" and retry.
Screenshot refused, mentioning a locked desktopBy design: the agent refuses to operate while the screen is locked or a UAC secure desktop is showing. Unlock the PC and retry.
A wrapper ends with _FAILEDThe reason is on that same line (missing app, file, or output). Check it first.
VV_FAILED no python foundCreate the .venv next to vv-say.ps1 (Step 4), or set VV_PYTHON to your Python.
VV_FAILED about the engineVOICEVOX is not installed, or its engine failed to start. Start VOICEVOX once by hand, then retry.

About safety

The Desktop Agent listens only on 127.0.0.1 (inside your own PC) and requires a per-user token. Every action is logged, and it can be stopped at any time from its tray icon or with a STOP file. It is a tool for your PC and your AI — please read SECURITY.md in the repository before use. The full written guide also lives on GitHub as SETUP.md.
